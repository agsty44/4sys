# Quick security review (initial)

This short review highlights the most important issues I observed during a read of the code. These are prioritized: high risk first.

1) Credentials in source (HIGH)
- `header.php` contains DB credentials in plaintext (example: user `root`, password `password`). Move credentials to environment variables or a config file outside the webroot and restrict Git commits.

2) Cookie flags (HIGH)
- `setcookie('auth_token', ...)` is used without `HttpOnly`, `Secure`, or `SameSite` options. Without `HttpOnly`, JS can read cookies (XSS risk). Without `Secure`, cookies may be sent over HTTP. Use the associative `setcookie()` options on PHP 7.3+ or set headers appropriately.

3) Token generation & storage (MEDIUM)
- Tokens are generated by hashing a decimal `random_int()` value with `password_hash()`. This has two drawbacks: limited entropy of `random_int(0..999999999999)` and using bcrypt for token storage is atypical (performance/semantics). Prefer `random_bytes(32)` + `bin2hex()` and store the token (or an HMAC) directly.

4) Cross-site scripting (MEDIUM)
- `admin/student_search/student_search.js` uses `insertAdjacentHTML` with unescaped values coming from the API (`OtherNames`, `LastName`). If any stored value in the DB contains HTML/JS, it will execute in the admin's browser. Use `textContent` or DOM methods to insert untrusted data.

5) Missing auth checks on admin helper pages (HIGH/MEDIUM)
- `TempAdmin/createuser.php` accepts POST and creates a user without checking the caller's access tier. Either restrict/remove this file or require `is_user_in_right_area(4)`.

6) Input validation & result limits (LOW/MEDIUM)
- `api/student_search.php` accepts `?query=` and searches with `LIKE` but has no server-side length checks or `LIMIT`. Add limits and a minimum query length to avoid abuse or heavy queries.

7) Error handling & info leakage (LOW)
- `header.php` dies with DB connection error text in some cases (commented-out error reporting exists). Avoid printing DB errors in production.

8) Path/include inconsistencies & small bugs (LOW)
- A missing slash was found in a prior `include()` call and fixed. Standardize include patterns and centralize path logic.

Recommendations (quick wins)
- Move DB credentials to env or a config file outside webroot.
- Add `HttpOnly`, `Secure`, and `SameSite` flags to the `auth_token` cookie.
- Replace the token generator with `bin2hex(random_bytes(32))` and store tokens directly.
- Sanitize or escape all data before inserting into the DOM; use `textContent` or createElement + setAttribute.
- Add `is_user_in_right_area(4)` guard to `TempAdmin/createuser.php` or remove it.
- Add server-side validation to `api/student_search.php` (min length, max length, LIMIT 50), and ensure `$_GET['id']` is validated as integer before use.
